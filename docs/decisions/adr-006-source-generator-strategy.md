# ADR-006: Source Generator Strategy

## Status
Accepted

## Date
2026-08-12

## Context
The library needs to produce entity metadata (table name, column names, property values) without runtime reflection in order to be AOT-compatible. The two options are: compile-time code generation (Roslyn Source Generators) or runtime reflection with caching.

## Problem
- Runtime reflection via `typeof(T).GetProperties()` breaks NativeAOT trimming
- Attributes + reflection is the "standard" Dapper.Contrib approach but excludes AOT
- We need metadata to be available at zero runtime cost for bulk operations, diff updates, and filter generation

## Options Considered

### Option A: Runtime reflection + caching (Dapper.Contrib style)
- Rejected: breaks NativeAOT, requires reflection attributes, cache invalidation complexity

### Option B: T4 templates
- Rejected: legacy approach, no IDE integration, no Roslyn integration, poor DX

### Option C: Roslyn Source Generator (IIncrementalGenerator)
- **Chosen**: Compile-time, full IDE support, no runtime cost, incremental compilation

### Option D: Manual implementation by user
- Rejected: too much boilerplate, error-prone, defeats library's value proposition

## Decision
All entity metadata is generated by `EricksonLopez.SqlBuilder.SourceGenerators` via a Roslyn `IIncrementalGenerator`.

**Trigger:** Classes decorated with `[SqlEntity]` attribute.

**Generated artifacts per entity `T`:**
- `T_SqlMetadata.g.cs` — implements `IStaticEntityMetadata<T>` with table name + column arrays
- `T_Filters.g.cs` — strongly-typed filter record with `WhereXxx()` extension methods
- Partial class extensions for `T` implementing `ISqlEntity`

**Naming convention:** `snake_case` for table/column names derived from PascalCase property names. Override with `[Column("name")]`.

**Invariant:** The Source Generator must NEVER emit code that calls `typeof(T).GetProperties()` or any other runtime reflection API.

## Consequences

### Positive
- ✅ Zero runtime allocation for entity metadata lookup
- ✅ Full NativeAOT compatibility
- ✅ Compile-time errors for invalid configurations
- ✅ IDE completion support for generated filter types
- ✅ No registration boilerplate (attribute is sufficient)

### Negative
- ❌ Longer build times (incremental, but still non-zero)
- ❌ Source Generator complexity vs. runtime reflection
- ❌ Debugging generated code requires enabling `EmitCompilerGeneratedFiles`

## AOT Impact
✅ Full NativeAOT safe — all code paths avoid runtime reflection.

## Reconsideration Criteria
If .NET ships a `[TypeMetadata]` intrinsic that produces reflection metadata at compile time without a Source Generator, evaluate replacing the generator with the intrinsic.
