# Bulk Operations — EricksonLopez.SqlBuilder

> **Packages:** Core (batched), Dialect packages (native strategies), `EricksonLopez.SqlBuilder.Dapper` (execution)
> **ADR:** [ADR-010](decisions/adr-010-bulk-api-architecture.md)

---

## Overview

Bulk operations efficiently persist large collections of entities to the database, dramatically reducing round-trips and execution time compared to single-row operations.

---

## Strategy Architecture

The library uses a pluggable `IBulkStrategy` model:

```
BulkInsertAsync(entities)
    │
    ├── Check registered IBulkStrategy implementations
    │       (registered by dialect packages at startup)
    │
    ├── If strategy found and can handle connection → use native strategy
    │       SQL Server: SqlBulkCopy
    │       PostgreSQL: NpgsqlBinaryImporter (COPY)
    │       MySQL: Multi-row VALUES
    │       SQLite: Prepared statement loop + WAL
    │
    └── Fallback: batched INSERT (multi-row VALUES with batch splitting)
```

---

## Current: Batched INSERT (v1.0)

Works on all providers without extra configuration:

```csharp
// Via InsertQuery (Core)
var query = Sql.BulkInsert(entities);
await connection.ExecuteAsync(query);

// Via BulkBuilder with AOT metadata (zero-allocation hot path)
var result = Sql.Bulk(entities).Insert().Build(renderer);
```

### Batch Size

Batch size is automatically managed to stay within provider parameter limits:

| Provider | Default Batch | Max Parameters |
|----------|--------------|----------------|
| SQL Server | 500 rows | 2100 |
| PostgreSQL | 2000 rows | 65535 |
| MySQL | 1000 rows | 65535 |
| SQLite | 50 rows | 999 |
| Oracle | 500 rows | 32767 |

## Planned: Native Strategies (v1.x)

### SQL Server — SqlBulkCopy

```csharp
// Registered automatically when SqlServer package is installed
DapperExtensions.RegisterBulkStrategy(new SqlBulkCopyStrategy());

// Usage (same API — strategy resolves automatically)
var result = await connection.BulkInsertAsync(entities, new BulkOptions
{
    BatchSize = 1000,
    ReturnIdentities = true,
    Transaction = tx,
    CancellationToken = ct
});
```

### PostgreSQL — COPY

```csharp
DapperExtensions.RegisterBulkStrategy(new NpgsqlCopyStrategy());

var result = await connection.BulkInsertAsync(entities, new BulkOptions
{
    BatchSize = 5000,
    ReturnIdentities = true // Uses RETURNING clause
});
```

### MySQL — MySqlBulkCopy / Batched VALUES

```csharp
DapperExtensions.RegisterBulkStrategy(new MySqlBatchStrategy());

var result = await connection.BulkInsertAsync(entities, new BulkOptions
{
    BatchSize = 1000,
    ReturnIdentities = true
});
```

### SQLite — Prepared Statement Loop

```csharp
// SQLite uses an optimized prepared statement loop wrapped in a transaction
DapperExtensions.RegisterBulkStrategy(new SqliteBatchStrategy());

var result = await connection.BulkInsertAsync(entities, new BulkOptions
{
    BatchSize = 50,
    ReturnIdentities = true
});
```

## BulkOptions (v1.x)

```csharp
public record BulkOptions
{
    public int BatchSize { get; init; } = 0; // 0 = auto (provider default)
    public bool ReturnIdentities { get; init; } = false;
    public IDbTransaction? Transaction { get; init; }
    public CancellationToken CancellationToken { get; init; }
    public TimeSpan? Timeout { get; init; }
}

public record BulkInsertResult<T>
{
    public int RowsAffected { get; init; }
    public IReadOnlyList<T>? EntitiesWithIdentities { get; init; }
}
```

## BulkUpdate and BulkDelete

### Current (v1.0)

```csharp
// Naive: uses Dapper's multi-row execute (loop)
await connection.BulkUpdateAsync(query, entities);
await connection.BulkDeleteAsync(query, entities);
```

### Planned (v1.x) — Temp Table Strategy (SQL Server)

For SQL Server bulk update, uses a temp table:
1. Bulk INSERT into `#temp`
2. JOIN `#temp` with target table
3. UPDATE / DELETE in single statement

This approach processes 10,000+ rows in seconds vs minutes.

## Bulk INSERT (AOT Path)

Using Source Generators for maximum performance:

```csharp
// Entity must have [SqlEntity] attribute
[SqlEntity]
public partial record User { /* ... */ }

// BulkBuilder<T> requires IStaticEntityMetadata<T> (generated by SourceGenerators)
// This path has ZERO allocations on the hot path
var renderer = new SqlServerAotRenderer();
var result = Sql.Bulk(users).Insert().Build(renderer);

await connection.ExecuteAsync(result);
```

BenchmarkDotNet must confirm `Allocated: 0 B` on this path.

## What Bulk Operations Are NOT

| Feature | Available? | Reason |
|---------|-----------|--------|
| Relationship bulk (1:N auto) | ❌ NEVER | ORM responsibility (ADR-001) |
| Navigation property hydration | ❌ NEVER | ORM responsibility |
| Change-tracked bulk | ❌ NEVER | No change tracking (ADR-007) |
| Server-side `IDENTITY` retrieval in bulk | ❌ NEVER | Protocol limitation; use Client-Generated Keys (UUIDv7) or `InsertQuery.Returning()` (ADR-046) |
